# SCHEMA.md — The Authoring Contract

> **What this is.** The single source of truth for *how* every artifact in **eq-sparks** is written. It is the contract between **canonical content** (what we author, in Claude Code format) and the **rendered IDE files** developers actually consume. If a file you are writing is an agent, a skill, or an orchestrator/command, its shape is defined here — and nowhere else.

eq-sparks is the central agentic-harness monorepo for the Equiniti frontend + BFF estate. It holds every agent, orchestrator, skill, guardrail, and the hidden "agentic OS" (cache, budget, memory), then syncs into consumer repos behind a gitignored `.eq-sparks/` folder. Authoring discipline is what keeps a 20–50-developer team — and a 23-agent roster running Haiku-first under budget — coherent. This document is that discipline.

---

## The rendering model: author once, project to two IDEs

**The canonical source is authored under the visible top-level layout and runs *now*.** You author exactly one file per artifact in the canonical tree, and **two IDE render adapters** project that ONE source into the native layouts each IDE executes — there is no hand-maintained `.claude/` or `.github/`. **NEVER edit `.claude/` OR `.github/` — both are generated. Edit the canonical source and re-render.**

- **`bin/render-claude.mjs`** → projects into the **`.claude/`** layout Claude Code executes.
- **`bin/render-copilot.mjs`** → projects into the **`.github/`** layout GitHub Copilot consumes.

Both adapters share the render core in `bin/render-lib.mjs` (no runtime dependencies, Node 18+). Each takes an optional `filter` (`{agents, skills, orchestrators}` = arrays of ids), so **the CLI (`cli/eq-sparks.mjs`) renders only the subset declared by the active `--profile`** — pass no filter to render everything. The hidden "agentic OS" (cache, budget, memory, **telemetry**) is NEVER rendered into an IDE folder — it lives only in `.eq-sparks/`.

### Canonical locations (the source of truth)

| Kind | Canonical path (author here) | Claude Code (`render-claude.mjs`) | Copilot (`render-copilot.mjs`) |
|---|---|---|---|
| **Agent** | `agents/<category>/<id>.md` (`category` ∈ `governance` \| `core` \| `frontend` \| `bff` \| `platform`) | `.claude/agents/<id>.md` (flattened) | `.github/agents/<category>/<id>.md` (grouped by category) |
| **Skill** | `skills/<id>/SKILL.md` | `.claude/skills/<id>/SKILL.md` | `.github/skills/<id>/SKILL.md` |
| **Orchestrator** | `orchestrators/<id>.md` | `.claude/commands/<id>.md` | `.github/chatmodes/<id>.chatmode.md` |
| **Guardrails** | `shared/guardrails/<id>.md` | (stays in `.eq-sparks/`) | `.github/instructions/<id>.instructions.md` |
| **Principles** | `instructions/<id>.md` | (stays in `.eq-sparks/`) | `.github/instructions/<id>.instructions.md` |

> Both `.claude/` and `.github/` are GENERATED. Every rendered file carries a "GENERATED by eq-sparks" banner inserted after the frontmatter. Edit the canonical source, then re-render.

### Adapter 1 — Claude Code (`bin/render-claude.mjs` → `.claude/{agents,skills,commands}`)

- **Agents flatten:** the canonical `agents/<category>/<id>.md` tree is projected to a flat `.claude/agents/<id>.md` (the `category` becomes frontmatter, not a directory). Ids stay globally unique across categories.
- **Orchestrators → commands:** `orchestrators/<id>.md` renders to `.claude/commands/<id>.md` (a Claude Code "command" is our orchestrator).
- **Skills pass through:** `skills/<id>/SKILL.md` → `.claude/skills/<id>/SKILL.md`, structure preserved.

### Adapter 2 — GitHub Copilot (`bin/render-copilot.mjs` → `.github/{chatmodes,agents/<category>,skills,instructions}` + `copilot-instructions.md`)

- **Orchestrators → chat modes:** `orchestrators/<id>.md` renders to `.github/chatmodes/<id>.chatmode.md` (chat modes are Copilot's orchestrator entry points). The frontmatter key is **rewritten**: our `allowed-tools:` becomes Copilot's **`tools:`** (the `allowed-tools` → `tools` mapping). Same tool list, IDE-native key.
- **Sub-agents stay grouped by category:** `agents/<category>/<id>.md` → `.github/agents/<category>/<id>.md` (Copilot keeps the category directories that Claude flattens away).
- **Skills pass through:** `skills/<id>/SKILL.md` → `.github/skills/<id>/SKILL.md`, structure preserved.
- **Guardrails + principles → instructions:** every `shared/guardrails/*.md` (the policies, incl. `guardrails-registry`) and every `instructions/*.md` (the universal principles, e.g. `eq-principles`) render to `.github/instructions/<id>.instructions.md` as path-scoped Copilot instructions.
- **Repo-wide index:** the adapter also writes `.github/copilot-instructions.md` — a generated index of where everything lives (chat modes, agents-by-category, skills, instructions) plus the governance-trio reminder.

Because there are two adapters, our frontmatter carries **optional canonical fields** alongside the Claude-required ones: Claude Code harmlessly ignores unknown keys, while the Copilot adapter reads them to render the richer category-grouped view. **Never** fork content into hand-maintained copies — author once, let both adapters project.

### Universal conventions (apply to all three kinds)

- **Everything is Markdown with required YAML frontmatter.** No frontmatter, no artifact.
- **Ids are kebab-case** (`shared-curator`, `dna-precheck`, `contract-sync`) and the **filename id must match the `name`/`id` in frontmatter**.
- **The `model` field is the cost lever.** It is the single knob that picks the price/quality tier per agent. Honour the **[[model-routing-policy]]** — `haiku` for mechanical/rule-based work, `sonnet` for codegen + specialists, `opus` for judgment (governance trio + architect + security).
- **Commands launch subagents via the `Agent` tool; subagents DO NOT launch further subagents.** Only the command (the main thread) orchestrates. Worker agents do their job and hand back.
- **Cross-references use exact ids only.** Reference other agents as `@<id>`, skills/commands/guardrails by their exact id. Never invent an id.
- **Memory links use `[[id]]`** double-bracket wiki-link syntax (e.g. `[[budget-policy]]`, `[[memory-schema]]`).
- **No secrets, no new runtime dependencies.** Honour [[safety-rails]] and [[path-policy]].

## Kind 1 — Agent (Claude Code subagent)

**Canonical location:** `agents/<category>/<id>.md` (`category` ∈ `governance` \| `core` \| `frontend` \| `bff` \| `platform`). **Rendered to** `.claude/agents/<id>.md` by `bin/render-claude.mjs` (agents flatten) and to `.github/agents/<category>/<id>.md` by `bin/render-copilot.mjs` (category-grouped) — never edit either rendered file.

A subagent is a single-purpose worker the orchestrator delegates to. It declares its capability, its cost tier, and the guardrails it inherits.

### Frontmatter

**Required by Claude Code:**

| Key | Type | Notes |
|---|---|---|
| `name` | string | Kebab-case, matches the filename and the `@<id>` used in cross-references. |
| `description` | string | **One line, specific** — used for auto-routing. Make it unambiguous so the orchestrator picks the right agent. |
| `model` | enum | One of `haiku` \| `sonnet` \| `opus`. **The cost lever** — set the default tier per [[model-routing-policy]]. |
| `tools` | csv | Comma-separated subset of: `Read, Edit, Write, Bash, Grep, Glob, WebFetch, TodoWrite`. Grant least privilege — read-only agents (e.g. `@architect`, `@reviewer`, `@security`) must not carry `Edit`/`Write`. |
| `loop` | enum | One of `autoresearch` \| `single-shot`. **The execution mode** — `autoresearch` runs the bounded converge loop (restate → search → read → hypothesise → act → verify → self-evaluate → iterate); `single-shot` does one focused pass (plan/decide/review/scan/check) then self-assess + handoff. |

**Optional canonical fields (carried in the same frontmatter for the future adapter; Claude Code ignores them):**

| Key | Type | Notes |
|---|---|---|
| `version` | string | SemVer of the spec. |
| `status` | enum | e.g. `draft` \| `active` \| `deprecated`. |
| `category` | enum | `governance` \| `core` \| `frontend` \| `bff` \| `platform` — must match the `agents/<category>/` directory. The Copilot adapter groups agents by this; Claude Code flattens it into frontmatter. |
| `uses_skills` | list | Exact skill ids this agent invokes (e.g. `[dna-precheck, self-evaluate]`). |
| `constraints` | list | Hard limits (e.g. read-only, path scope). |

```yaml
---
name: shared-curator
description: Detects duplicated/common code across MFEs and moves it to eq-one-shared; flags dead code.
model: sonnet
tools: Read, Edit, Write, Grep, Glob
loop: autoresearch
# --- optional canonical (adapter-only) ---
version: 0.1.0
status: active
category: frontend
uses_skills: [dna-precheck, move-to-shared, self-evaluate]
constraints: [no-cross-repo-writes-outside-path-policy]
---
```

### Body headings (in this order)

1. **Role** — One paragraph: what this agent owns and what it explicitly does not.
2. **When to invoke / When NOT** — Two short lists. Sharp boundaries prevent the orchestrator from over-delegating and burning budget.
3. **Model tier & escalation** — State the default tier and the **escalation trigger**: escalate **one rung only** on low self-eval confidence (`<0.7`) or **two critic FAILs**; the escalation is logged + budgeted; **never auto-downgrade**. (Defined by [[model-routing-policy]].)
4. **Budget & guardrails (inherited)** — Name the guardrails the agent obeys: [[budget-policy]], [[path-policy]], [[safety-rails]], [[cache-policy]], [[dedup-policy]]. Note any path scope.
5. **Skills it uses** — Exact skill ids. **Build agents run `dna-precheck` first and `self-evaluate` last.** Fetch/scan agents use `cache-lookup`.
6. **Execution loop** — State the agent's `loop` mode and spell out the steps it runs. `autoresearch` agents follow the bounded A-Rag loop (restate → search → read-through-cache → hypothesise → act → verify → **`self-evaluate`** → iterate within budget, escalating one rung on confidence `<0.7` or two `@critic` FAILs). `single-shot` agents do ONE focused pass (plan/decide/review/scan/check), then self-assess + handoff — no converge loop. **writesDiff agents run the diff-based `self-evaluate` as the mandatory last step; read-only/gate/planning agents self-ASSESS their report's completeness + confidence instead** (an empty diff must never read as FAIL).
7. **Done criteria** — The objective definition of "handed off clean" (e.g. self-eval ≥ 0.7, @critic PASS).
8. **Failure modes (`BLOCKED:<reason>`)** — How the agent halts and reports. Always emit a `BLOCKED:<reason>` string the orchestrator can read (e.g. `BLOCKED:contract-drift`, `BLOCKED:missing-pbi-context`).
9. **Anti-patterns** — What this agent must never do (e.g. hand-roll a design-system component, write business logic into a BFF shaper).
10. **Handoff** — Emit a structured handoff envelope (NOT free text) to the next agent / `@supervisor` via the `handoff` skill. Envelopes are stored under `.eq-sparks/agent-memory/<run-id>/handoff/<seq>-<from>-to-<to>.json`; the orchestrator routes the latest envelope addressed to the receiving agent, and `@supervisor` aggregates all envelopes into the Summary. (See the agent-memory runtime under [[memory-schema]].)

## Kind 2 — Skill

**Canonical location:** `skills/<id>/SKILL.md`. **Rendered to** `.claude/skills/<id>/SKILL.md` (Claude) and `.github/skills/<id>/SKILL.md` (Copilot), structure preserved — never edit either rendered file.

A skill is a reusable, deterministic-where-possible primitive that agents and orchestrators call. Skills are where caching is declared.

### Frontmatter

**Required:**

| Key | Type | Notes |
|---|---|---|
| `name` | string | Kebab-case, matches the folder id. |
| `description` | string | One line — what the skill does and when it fires. |

**Optional:**

| Key | Type | Notes |
|---|---|---|
| `kind` | string | e.g. `primitive`, `mcp`, `render`. |
| `id` | string | Explicit id if it differs from folder name (keep them equal). |
| `version` | string | SemVer. |
| `status` | enum | `draft` \| `active` \| `deprecated`. |
| `mcp` | string | The MCP server backing the skill (e.g. `ado`, `figma`) for skills like `ado-context` / `figma-context`. |
| `cacheable` | bool | **Critical.** `true` only for safe-to-cache reads. **NEVER cache writes/tests/self-eval/LLM completions** per [[cache-policy]]. |

```yaml
---
name: contract-diff
description: Diffs a domain's ExperienceAPI OpenAPI contract against FE TS types/clients and reports drift.
kind: primitive
version: 0.1.0
status: active
cacheable: true
---
```

The new **`handoff`** skill writes/reads the agent→agent handoff envelope (never cacheable — it mutates run state):

```yaml
---
name: handoff
description: Writes/reads the structured agent→agent handoff envelope under .eq-sparks/agent-memory/<run-id>/handoff/.
kind: primitive
version: 0.1.0
status: active
cacheable: false
---
```

> **Agent-memory runtime.** The `handoff` envelope and the rest of the per-run working memory live under the gitignored `.eq-sparks/agent-memory/<run-id>/` runtime per [[memory-schema]]: `scratchpad.md` (Layer-1 per-run memory), `ledger.jsonl` (idempotent task ledger), `handoff/<seq>-<from>-to-<to>.json` (the envelopes), and `metadata.json`. The envelope schema is `{ run_id, seq, from_agent, to_agent, stage, task, hypothesis, decisions[], artifacts{reuse,extend,create}, files_touched[], diff_summary, self_eval{passed,confidence,unmet[]}, open_items[], budget{tool_calls_used,remaining}, next }`. Committed templates live in `shared/memory/templates/`.

### Body headings (in this order)

1. **Description** — What it does, in one short paragraph.
2. **Inputs** — Named inputs and types. (These form the cache key with `skill_id` + `version`.)
3. **Outputs** — The shape the caller receives.
4. **Tools Needed** — Which Claude tools the skill relies on.
5. **Constraints** — Including **`cacheable`** (and the cache key: `(skill_id, version, input_hash)`) and **`fail_modes`** (the `BLOCKED:<reason>` strings it can emit). Reaffirm [[cache-policy]]: never cache writes/tests/self-eval/LLM completions.
6. **When to invoke** — The triggering condition.
7. **How it works** — The step sequence.
8. **Anti-patterns** — Misuses to avoid (e.g. caching a write, treating MCP context as a write target).

## Kind 3 — Orchestrator / Command

**Canonical location:** `orchestrators/<id>.md`. **Rendered to** `.claude/commands/<id>.md` (Claude: orchestrator → command) and `.github/chatmodes/<id>.chatmode.md` (Copilot: orchestrator → chat mode) — never edit either rendered file. For the Copilot chat mode the frontmatter `allowed-tools:` key is rewritten to `tools:` (the `allowed-tools` → `tools` mapping); the tool list is unchanged.

A command is the main-thread orchestrator. It plans stages, launches subagents, enforces the governance gate, and renders the console. **It is the only place the `Agent` tool is used.**

### Frontmatter

**Required:**

| Key | Type | Notes |
|---|---|---|
| `description` | string | One line — what the orchestrator achieves. |
| `argument-hint` | string | The expected `$ARGUMENTS` shape shown to the user (e.g. `<ado-pbi-id>`). |
| `allowed-tools` | csv | **MUST include `Agent`** so the command can launch subagents. Add only the other tools the main thread genuinely needs. The Copilot adapter renders this key as **`tools:`** in the chat mode (`allowed-tools` → `tools`); the value is identical. |

```yaml
---
description: Turn an ADO PBI into a cross-repo-aware, governed scaffold.
argument-hint: <ado-pbi-id>
allowed-tools: Agent, Read, Grep, Glob, TodoWrite
---
```

### Body (required content)

- **Use `$ARGUMENTS`** in the body to consume the command input.
- **The staged flow** — The ordered stages. The standard governance flow: **`@supervisor`** plans stages + budget → worker agents produce → **`@critic`** returns strict PASS/FAIL (a **FAIL BLOCKS** the stage) → **`@supervisor`** makes the go/no-go call. **`@decision`** resolves any ambiguity with a logged, defensible call.
- **Which agents it delegates to and when** — Name each `@<id>` against its stage. Build agents run `dna-precheck` first and `self-evaluate` last; fetch/scan agents use the cache.
- **Console usage** — Call `console-render` to emit the standardised three-part console: **Intro card, per-stage block, Summary**. Run `budget-check` against the ceiling from [[budget-policy]].
- **Steps** — The concrete, numbered execution steps.
- **Usage** — Example invocations (e.g. `/scaffold 12345`).

> **Reminder:** the command launches subagents; **subagents never launch further subagents**. Keep orchestration in the main thread.

## Other canonical artifacts (not one of the three IDE-rendered kinds)

Two more bodies of content are authored canonically. They are NOT subagents/skills/orchestrators, so they have their own homes and render targets.

### Guardrails — `shared/guardrails/<id>.md`

The guardrail policies are the harness's law: [[guardrails-registry]], [[budget-policy]], [[model-routing-policy]], [[dedup-policy]], [[safety-rails]], [[path-policy]], [[cache-policy]] (plus `memory-schema` under `shared/memory/`). **`guardrails-registry` is the canonical index** — the G1…Gn table mapping each guardrail to its scope, enforcing agent, and enforcement point; every agent's "Budget & guardrails (inherited)" heading names the rails it obeys, and `safety-rails` carries the agent-level detail. The Copilot adapter renders each `shared/guardrails/*.md` to `.github/instructions/<id>.instructions.md`; Claude Code reads them in place from `.eq-sparks/`. Never edit the rendered instructions — edit the canonical policy.

### Telemetry / observability — `shared/telemetry/`

The observability contract is authored under `shared/telemetry/`: `telemetry-schema.md` (the one-JSONL-event-per-action schema agents and skills emit), `sinks.md` (the pluggable sink model — DEFAULT local `.eq-sparks/telemetry/<run-id>.jsonl`, which works today), and `newrelic-sink.md` (the config-gated NewRelic sink: `telemetry.sink: local|newrelic` in `.eq-sparks.yml`, `newrelic.enabled: false` by default, `account_id` + license via ENV/secret store — **never committed**). `@infra` reads whichever sink is active; until NewRelic is provisioned the local sink is authoritative and nothing blocks. Telemetry is part of the hidden "agentic OS" — it lives in `.eq-sparks/` and is **never rendered into an IDE folder** by either adapter.
